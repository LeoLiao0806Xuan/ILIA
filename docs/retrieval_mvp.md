# ILIA 混合检索与证据选择

## 检索路径

1. 查询含明确文书名和条/段号时，直接走结构化精确定位。
2. 只有文书名时，返回文书元数据。
3. 自然语言查询同时运行 FTS5 和 BGE-M3 dense 向量检索。
4. FTS5 首先采用 AND 查询；严格查询为空时才回退到 OR，以兼顾精度和自然语言改写。
5. 核心库与个人资料库分别查询，在 Rust 层按带资料库命名空间的稳定键合并。
6. 各路最多取 30 个候选，使用 Reciprocal Rank Fusion 合并：`score = Σ 1 / (60 + rank)`。
7. 精确条/段、文书名、案名和年份获得确定性加权；融合后执行重复压缩、单文书配额和相邻内容合并。

资料库、文书类型、主题和指定文书过滤均下推到精确定位、FTS5 与向量 SQL 查询。主题来自版本化人工元数据 `corpus/manifests/document_topics.v1.json`；主题过滤启用时，尚无可信主题映射的个人资料不会越界进入结果。英文文书名支持编辑距离不超过 2 的保守错拼匹配；罗马数字条号会先转换为阿拉伯数字再定位。

## 向量存储

- 模型：`gpahal/bge-m3-onnx-int8`，上游为 `BAAI/bge-m3`。
- 维度：1024。
- 格式：little-endian float32 BLOB，每条 4096 字节。
- v1.0.0 基线规模为 5,254 个内容单元；下一版 49 文书规范化发布库为 5,093 个内容单元，全部已建立 FTS5 与 BGE-M3 索引。
- 当前向量查询采用 SQLite 顺序扫描和余弦相似度；这一规模下实现简单且可复现。资料量明显扩大后再迁移到 HNSW，不提前引入额外索引依赖。

## 证据选择

最终排序结果最多返回 10 条；默认选择前 5 条作为证据，并受 12,000 字符总预算限制。默认单文书最多保留 3 条候选；同一文书中定位类型一致且顺序相邻的内容会合并为一项证据。每条证据保留稳定键、主 chunk ID、关联 chunk ID、可读引证、原文、排名和选择原因，可直接提供给后续本地生成模型。

## 当前评测

v1.0.0 基线评测集共 200 题、覆盖 50 份资料，结果为 200/200。v1.0.1 排除 ICRC 习惯国际人道法规则后使用 197 题评测集，结果为 197/197，Recall@5 和 Recall@10 均为 1.0，Recall@1 为 0.9792，MRR 为 0.9865。

1.1 开发评测集 `tests/eval/retrieval_1.1.jsonl` 共 305 题，包含上述 197 题可比基线以及中英文规范名、别名、罗马数字条号、错拼和过滤负例。2026-09-25 使用实际 BGE-M3/ONNX Runtime 重跑结果为 305/305：Recall@1 0.9868、Recall@5 0.9967、Recall@10 1.0、MRR 0.9904、精确条款定位 1.0、双语文书名识别 1.0、过滤用例通过率 1.0、过滤逃逸 0。开发证据写入 `data/retrieval_eval_report_1.1.0-dev.json`。

`python tools/build_retrieval_eval_1_1.py --check` 会从核心数据库重建期望内容并校验已提交评测集，同时确认主题元数据没有引用不存在的文书；CI 使用同一检查防止静默漂移。
